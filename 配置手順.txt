技術士 問題Ⅰドリル（四択アプリ） 配置手順
=============================================
※ RCCM（rccm-takuitsu-web）とは別のリポジトリにする。RCCMのファイルには手を付けない。

■ 一式の中身
  index.html ……… アプリ本体（RCCM配布版の形式を流用）
  data/ …………… manifest.json と各シートのJSON（KA_1.json〜ND_2.json の16ファイル）
  gas/ExportDrill.gs …… スプレッドシート用のGAS（GitHubには上げなくてよい）
  README.md

■ 1. 初回の公開（GitHub Pages）
  1. GitHubで新規リポジトリを作成（Public）。名前の例：pe-mondai1-drill
  2. 「uploading an existing file」で index.html・data フォルダ・README.md をまとめてアップロード
     ※ index.html がリポジトリ直下に来るように
  3. Commit changes
  4. Settings → Pages → Deploy from a branch → main → /(root) → Save
  5. 1〜2分後に表示されるURLを開く（スマホ／タブレット／PC）
  ※ data/ の中身は 問題Ⅰドリル.xlsx（11/2版）から作ったもの。最初はこのまま使える。

■ 2. スプレッドシートの準備（1回だけ）
  1. 問題Ⅰドリル.xlsx をGoogleドライブに置き、「Googleスプレッドシートとして保存」する
     （以後の修正はこのスプレッドシートで行う。RCCMのスプレッドシートとは別のフォルダに置く）
  2. 拡張機能 → Apps Script を開き、gas/ExportDrill.gs の中身を貼り付けて保存
  3. スプレッドシートを開き直すと、メニューに「問題Ⅰドリル書き出し」が出る
     ※ 初回は承認画面が出る（ドライブへの書き込みのため）

■ 3. 問題を直したとき・足したとき
  1. スプレッドシートを修正する（ID・公開○のルールは「使い方」シートのとおり）
  2. メニュー「問題Ⅰドリル書き出し」→「JSONを書き出す（検証あり）」
     ・エラーがあると中止し、どの行が悪いかを表示する（ID重複、正答が1〜4でない、IDとシート名の不一致など）
     ・書き出し先：スプレッドシートと同じフォルダの中の「問題Ⅰドリル_data」フォルダ
       （RCCMの manifest.json は探さないので、上書きの心配はない）
  3. 「問題Ⅰドリル_data」の中身（manifest.json と各JSON）をダウンロードし、
     GitHub の data/ に上書きでアップロード → Commit changes
  4. 数分後、アプリを開き直すと反映される

■ 4. 「知識」を追加するとき
  ・「建設_知識_1」「農業_知識_1」のようにシートを作る（列は他と同じ、IDは KE001／NE001 から）
  ・GASの TYPES には「知識（E）」を登録済み。書き出せば種別の一番下に出る

■ 5. 利用制限（index.html 冒頭の LICENSE）
  name: "社内限定"（透かし）／ accessCode: ""（なし）／ expiry: ""（期限なし）

■ 6. 記録について
  ・解答ごとに、問題ID・日時・解答時間・正誤を端末に保存する（スマホとPCの記録は別々）
  ・メニュー下の「学習記録を見る」で、日ごとの解答数・正答率・平均解答時間と、直近2週間の学習日数が見られる
  ・保存名は drill1_ で始まり、RCCM（rccm_）の記録とは混ざらない
  ・ブラウザの履歴・サイトデータを消すと記録も消える
